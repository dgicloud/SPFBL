# Core SPFBL nativo e proxy de administração

O bundle compila o core SPFBL em Java 8, com um ajuste HAD de apresentação na coluna Entrega em `ServerHTTP.java`; o protocolo, políticas e dados do SPFBL permanecem inalterados. O serviço executa em Java 11 ou superior e não depende de Docker. A configuração habilita matrix.hadcloud.srv.br, HTTP interno em 8080 e P2P. O listener de consulta TCP 9877 usa o protocolo upstream original e a firewall nftables da VM permite apenas os IPs cadastrados. UDP 9877 permanece disponível para P2P. ADMIN TCP 9875 fica bloqueada externamente; o backend HTTP 8080 segue privado e o Nginx o acessa por loopback para publicar o painel em HTTPS. Na VM `matrix.hadcloud.srv.br`, o acesso externo a TCP 8080 é redirecionado por uma tabela nftables separada para Nginx/TLS 443, que atende HTTP legado e HTTPS e responde com 301 para o endereço HTTPS sem porta; a regra e o drop-in persistente estão em `dnsbl-link-override.nft` e `had-antispam-firewall-dnsbl-link.conf`.

O listener DNSBL upstream está ativo na VM com `dnsbl_port=53`. As zonas SPFBL configuradas incluem `dnsbl.hadcloud.com.br` e `rbl.hadcloud.srv.br`; a zona `rbl` está publicada no DNS autoritativo Bunny por `rbl NS matrix.hadcloud.srv.br.` e foi testada via `8.8.8.8`. `dnsbl.hadcloud.com.br` ainda aguarda delegação em sua zona autoritativa; o A já existente `dnsbl.hadcloud.srv.br` foi preservado, então o nome público escolhido para a lista é `rbl.hadcloud.srv.br`. O TXT SPFBL ainda gera `http://matrix.hadcloud.srv.br:8080/...`; na VM ativa, a regra opcional de redirecionamento encaminha essa porta ao Nginx em 443, que redireciona para a página HTTPS sem expor o backend. Para reproduzir a configuração, instale `dnsbl-link-override.nft` em `/etc/had-antispam/dnsbl-link.nft` e `had-antispam-firewall-dnsbl-link.conf` no diretório drop-in `had-antispam-firewall.service.d`, depois execute `systemctl daemon-reload` e reinicie `had-antispam-firewall.service`. Edite o IP de destino se a VM mudar de endereço. O unit concede somente `CAP_NET_BIND_SERVICE` ao processo `hadantispam`, necessário para abrir UDP 53 sem executar o core como root. Em Ubuntu com `systemd-resolved`, desative o stub em `/etc/systemd/resolved.conf` (`[Resolve]` / `DNSStubListener=no`) e use `/run/systemd/resolve/resolv.conf` como `/etc/resolv.conf`; confira que a VM ainda resolve nomes pelo DNS upstream. A firewall da VM e o security group do provedor precisam permitir INPUT UDP 53. Veja a [wiki upstream de DNSBL](https://github.com/leonamp/SPFBL/wiki/Como-criar-um-Servidor-DNSBL-com-o-SPFBL) e o [laudo da instalação ativa](../../docs/NATIVE-DEPLOYMENT-REPORT.md).

No Windows com Docker Desktop, gere o bundle chamando packaging/native/build-bundle.ps1 com uma versão única, por exemplo 1.1.0-had-20261002. Transfira e extraia o arquivo had-antispam-VERSAO.tar.gz na VM, confira /etc/had-antispam/allowed-cpanels.txt e execute sudo ./install.sh. O bundle inicial contém apenas o IP de homologação 177.39.18.160/32. Cada cPanel adicional precisa de seu IP/CIDR público de saída nessa allowlist. Atualizações preservam configuração e estado e mantêm a release anterior em releases/.

O instalador usa `/opt/spfbl`, seguindo a estrutura nativa documentada pelo upstream, e mantém configurações, dados e logs gerenciados pela HAD em `/etc/had-antispam`, `/var/lib/had-antispam` e `/var/log/had-antispam`. A alteração Java local é limitada à apresentação na coluna Entrega; P2P, protocolo, políticas e persistência continuam no core SPFBL. Não remove o checkout ou os dados Docker de desenvolvimento/homologação. Para reversão de uma atualização, a release anterior permanece em `/opt/spfbl/releases/`. Um timer systemd chama `STORE` diariamente às 01:00 de São Paulo, seguindo a recomendação upstream de gravação periódica do cache. O comando de parada aguarda o PID principal sair antes de devolver controle ao systemd, para que o core termine a persistência. O smoke isolado valida SPF, VERSION e FIREWALL sem ativar hostname, HTTP ou P2P dentro do laboratório.

O protocolo upstream em TCP 9877 é texto sem TLS; mantenha a allowlist atualizada na firewall da VM. O cPanel continua usando CSF/iptables localmente; o filtro deste bundle atua somente na VM SPFBL. O arquivo nginx-matrix.conf publica o login nativo do SPFBL através de HTTPS, protege cookies e reescreve as URLs HTTP geradas pelo core para o hostname público. Mantenha ADMIN TCP 9875 bloqueado externamente e o backend HTTP 8080 privado; o listener ADMIN do core faz bind em wildcard, então esse isolamento depende da regra de firewall e deve ser verificado após mudanças. Se o DNSBL emitir links na porta 8080, a VM desta implantação usa a tabela `dnsbl-link-override.nft` para redirecionar essa porta ao listener TLS do Nginx, com error_page 497 para HTTP puro e redirect canônico para Host com :8080. O P2P básico usa UDP 9877: além da regra local, libere entrada e saída UDP no firewall/security group do provedor. O listener secundário P2PS é opcional e exige reCAPTCHA e HTTPS nativo. O instalador não ativa a ACL do Exim: primeiro instala-se o transporte MONITOR no cPanel, valida-se conectividade e só então se pode instalar o hook MONITOR usando integrations/cpanel/manage_exim_acl.py.

O bundle também instala `had-antispam-backup` e `had-antispam-restore`. O backup faz STORE/shutdown ordenado e interrompe temporariamente as consultas; produz arquivos privados em `/var/backups/had-antispam`. Primeiro valide um arquivo com `had-antispam-restore ARQUIVO --dry-run`; a aplicação exige `--yes`, mesma release e cria snapshot `pre-restore`. O pacote preserva `data/server.key` junto ao restante de `data/`, `history/` e `/etc/had-antispam`. Consulte `docs/BACKUP-RESTORE.md` no repositório para limites e transferência segura.

`had-antispam status` é uma leitura local: informa unit, versão consultada no ADMIN loopback, release ativa, timer de persistência e contagens anonimizadas de `PEER SHOW`. A atividade recente é o intervalo informado pelo SPFBL, não uma conexão persistente; cap positivo não prova que uma mensagem usou reputação do peer. Falha ao ler peers não derruba o status do core. O serviço `had-antispam-observability.service` expõe `/health` e `/metrics` somente em `127.0.0.1:9911`; não crie proxy público para essa porta. `/health` valida a unit e a resposta `VERSION`; `/metrics` publica estado das units, resumo anonimizado de peers (com cache curto) e memória, CPU e descritores do processo quando `/proc` permite leitura. O resumo não inclui hostname, IP ou e-mail dos peers. Consulte `docs/OBSERVABILITY.md`.
